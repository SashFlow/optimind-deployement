---
title: ID verification
description: Tool-triggered ID card capture during web sessions via LiveKit RPC.
---

Identity verification is **not** a mandatory popup on join. When ID verification is
enabled (independently of proctoring), the agent opens the capture overlay by calling
LiveKit RPC `start_id_capture` on the candidate (typically from a Python `@function_tool`).

After a good frame is detected, the web client uploads two JPEGs to the backend and
notifies the agent via `add_context`.

## Setup

1. In **Call Session**, enable **ID verification**
   (“Allow the agent to request ID card capture during the session (via a tool call).”).
   Proctoring does **not** need to be enabled.
2. Create an org **Python tool** (Tools → Create Python tool) and paste the sample below.
3. Attach that tool to the agent so the model can call `verify_identity` mid-session.
4. Start a web (share / embed / preview) session with the camera on.

## Flow

```
Agent tool verify_identity
  → perform_rpc("start_id_capture") on candidate
  → Client opens ID overlay and scans camera frames
  → POST /sessions/{id}/participant-files  (id-card.jpg)
  → POST /sessions/{id}/participant-files  (id-card-full.jpg)
  → POST /sessions/{id}/id-card-ocr  (fast Gemini OCR → idType + fields)
  → Client perform_rpc("add_context") with type "id_captured" + OCR details
  → Agent chat gets a system message with OCR; agent can verify document type
```

### RPC: `start_id_capture` (agent → candidate)

- Registered only when `session_modalities.proctoring.id_verification` is true.
- Payload: empty string (or unused).
- Response: `{"started": true}` (JSON string).

### Upload: participant files

Authenticated with the candidate’s LiveKit participant JWT:

| Name | Content |
|------|---------|
| `id-card.jpg` | Cropped ID card JPEG |
| `id-card-full.jpg` | Full-frame evidence JPEG |

Endpoint: `POST /sessions/{id}/participant-files` (see [worker contract](/docs/sessions/worker-contract)).

### OCR: mid-session ID fields

After upload the client calls `POST /sessions/{id}/id-card-ocr` (same participant JWT).
A fast multimodal model (`gemini-3.1-flash-lite` by default, overridable with
`ID_CARD_OCR_MODEL`) reads the cropped card and returns structured fields. The result is
also stored on the session under `metadata.idCardOcr`.

```json
{
  "ocr": {
    "idType": "Aadhaar",
    "extracted": {
      "fullName": "...",
      "documentNumber": "...",
      "dateOfBirth": "...",
      "expiryDate": "",
      "issueDate": "",
      "nationality": "",
      "address": "...",
      "sex": "",
      "fatherName": ""
    },
    "confidence": 0.92,
    "summary": "Readable Aadhaar card.",
    "model": "gemini-3.1-flash-lite"
  }
}
```

OCR failures do **not** block capture: the client still sends `id_captured`, just without
`details.ocr`.

### RPC: `add_context` (candidate → agent)

After a successful upload (and OCR when available) the client injects a **system message**
into the agent session via `add_context` (worker: `role="system"`, then `generate_reply`
so the agent continues). When OCR succeeds, `details.ocr` is included so the agent can
check that the scanned document type matches what it requested:

```json
{
  "state": "ID card capture completed successfully. OCR results for the scanned document are included in the details for your reference. Confirm the document type matches what you requested, then continue.",
  "action": "generate_reply",
  "type": "id_captured",
  "details": {
    "confidence": 0.0,
    "capturedAt": 0,
    "status": "completed",
    "ocr": {
      "idType": "Aadhaar",
      "extracted": { "fullName": "...", "documentNumber": "..." },
      "confidence": 0.92,
      "summary": "Readable Aadhaar card.",
      "model": "gemini-3.1-flash-lite"
    }
  }
}
```

## Sample Python tool

Paste into **Create Python Tool**. The worker injects `host` (`.agent`, `.ctx`, `.state`).

```python
@function_tool()
async def verify_identity(self, context: RunContext) -> str:
    """Ask the candidate to show their ID card for verification.

    Call this when you need the candidate to present a government ID.
    The browser opens a capture overlay. Wait for confirmation that
    the ID was submitted before continuing sensitive steps.
    """
    try:
        room_io = context.session.room_io
    except RuntimeError:
        return "error: room not available yet"

    participant = room_io.linked_participant
    if participant is None:
        return "error: no candidate participant in the room"

    try:
        response = await room_io.room.local_participant.perform_rpc(
            destination_identity=participant.identity,
            method="start_id_capture",
            payload="",
        )
        return f"ID capture request sent: {response}. Waiting for candidate to submit ID."
    except Exception as e:
        return f"error: failed to start ID capture: {e}"
```

### How to test

1. Enable ID verification on the agent (proctoring optional).
2. Add the Python tool above and attach it to the agent.
3. Join a share/embed/preview session with camera enabled.
4. Ask the agent to verify your identity (or otherwise invoke `verify_identity`).
5. Hold an ID inside the guide frame until capture succeeds.
6. Confirm toast “ID card captured” and that `id-card.jpg` / `id-card-full.jpg` appear on the session’s participant files.
